# GARD BOOK Library — 배포 전 수락 시험

## A. 1차 구현 QA (코드에서 확인)
- [x] Owner는 임의의 이메일 문자열을 클라이언트에서 제출해 권한을 주장할 수 없음: Identity 검증 이메일로 서버에서 오너 판정
- [x] 게시 JSON 화이트리스트: 비공개 메모, 파일 경로, 원본 fullText 등 전달되지 않음
- [x] 7개 분류, BOOK ID, 메타데이터 형식 유효성 검사
- [x] 비승인/철회/만료 구독자 도서 조회 불가 (단위시험)
- [x] 구독자별 BOOK ID 범위 분리 (단위시험)
- [x] 게시 철회시 구독자 접근권에서 해당 BOOK ID 제거
- [x] 브라우저 원장 AES-GCM 암호화 및 잘못된 암호 거부
- [x] Netlify Deploy Preview는 데이터 API를 차단 (`CONTEXT=production`만 허용)
- [x] PDF 업로드와 다운로드는 실제 게시 및 서버 권한 검사 적용
- [x] 정적 Github 소스에 원고 원본/33종 JSON 미포함

## B. 서버에서 반드시 다시 확인할 E2E (아직 미실행)
- [ ] GitHub → Netlify 첫 빌드 및 배포 성공
- [ ] GARD_OWNER_EMAIL 환경변수 설정·재배포, 오너 계정 초대
- [ ] 초대 링크를 통한 비밀번호 설정·로그인
- [ ] 33종 private JSON 가져오기, 새로고침 후 동일 암호로 복구
- [ ] 오너가 1종 승인 게시하고 구독자별 승인 전에는 열람 불가
- [ ] 구독자 A에게 BOOK-001만, 구독자 B에게 BOOK-002만 승인
- [ ] A에서 BOOK-002 조회/파일 다운로드 → 403 거부 확인
- [ ] A에서 BOOK-001 게시 PDF 다운로드 가능
- [ ] 구독자 A 권한 철회 후 재로그인 없이 API 조회/다운로드 거부
- [ ] 종료일 이후 새 요청 거부
- [ ] 오너의 비공개 메모 수정 후 네트워크 트래픽에 노출 없음
- [ ] 구독자 로컬 임의 조작으로 오너 기능/API 실행 불가
- [ ] 안드로이드 Chrome에서 화면·검색·상세보기·다운로드 확인
- [ ] 별도 브라우저에서 초대·서버 인증·로컬 원장 분리 확인
- [ ] 암호화 백업 파일 복구, 잘못된 암호로 복구 실패 확인
- [ ] 실제 계약 권리, 개인정보, 원문 PDF 공개 범위의 오너 최종 승인

## C. 운영 주의
1. Netlify 서비스 및 비용 제한이 변경될 수 있으므로 실제 플랜 확인이 필요합니다.
2. 사용자의 승인에 따라 서버에 게시한 PDF는 암호화 원장이 아니라 **서버 접근통제**로 관리됩니다.
3. 동시 관리자 편집은 허용하지 않습니다. 서버 메타데이터에 간단한 버전 검사를 적용했습니다.
4. Blobs는 트랜잭션 DB가 아닙니다. 많은 구독자와 동시 갱신, 금융 거래 및 법정 증명 보관에는 별도 DB와 감사 체계를 적용하세요.

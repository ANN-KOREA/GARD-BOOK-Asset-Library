# GARD BOOK Asset Library™ v1.0

**GitHub 소스 + Netlify 배포 + Netlify Identity 로그인 + Netlify Functions 권한검사 + Netlify Blobs 선택 게시 + 브라우저 AES-GCM 로컬 원장**

## 이 앱은 무엇을 하나요?

- 오너: 기존 대화에서 발굴한 `GARD_BOOK_Discovery_Catalog_20261117.json`의 **33개 BOOK을 수동으로 가져오기**. 원본 메타데이터와 비공개 메모를 **암호화하여 해당 브라우저에 저장**합니다.
- 오너: 각 책의 **공개용 요약·구독자용 본문만 명시적으로 게시**합니다. 오너의 비공개 메모·원본 파일명·대화 원문은 게시되지 않습니다.
- 오너: 승인 구독자의 이메일과 BOOK별 허용 목록, 만료일을 관리하며 승인·철회 이력을 확인합니다.
- 오너: **게시된 BOOK에 한해** PDF 원고(4MB 이하)를 **별도 확인 후 업로드**할 수 있습니다.
- 구독자: Netlify Identity 계정으로 로그인한 뒤 **서버가 허용한 BOOK만** 확인하고, 명시적으로 게시된 PDF만 내려받습니다.

> **배포 후 처음에는 BOOK이 0종입니다.** 이는 개인정보와 비공개 자료를 실수로 깃허브에 게시하지 않기 위한 의도입니다. 33종 JSON 파일은 소스 ZIP에 포함하지 않았습니다.

## 1. 파일 준비하기 — GitHub

1. `GARD_BOOK_Asset_Library_GitHub_Netlify_v1.zip`을 내 컴퓨터에서 압축 해제합니다.
2. GitHub에서 **비공개(Private)** 새 저장소 `GARD-BOOK-Asset-Library`를 만듭니다.
3. 압축해제된 `index.html`, `package.json`, `netlify.toml`, `src/`, `shared/`, `netlify/`, `tests/` 등의 **파일과 폴더를 저장소 최상위 루트에 업로드하고 Commit**합니다.
4. **ZIP 파일 자체를 저장소에 올리는 방식으로는 배포되지 않습니다.** 파일을 풀어 실제 프로젝트 구조를 올려야 합니다.
5. `GARD_BOOK_Discovery_Catalog_20261117.json`, 원고 PDF/DOCX, 비공개 영업비밀 파일은 저장소에 올리지 마세요. **Private GitHub 저장소라도 원본 유출 예방이 필요합니다.**

## 2. Netlify에 GitHub 연결하기

1. Netlify에 로그인 → **Add new project / Import an existing project** → GitHub 연결.
2. 위 저장소를 선택합니다.
3. **Build command:** `npm run build`
4. **Publish directory:** `dist`
5. **Functions directory:** `netlify/functions` (`netlify.toml`에 이미 설정됨)
6. Node 22 이상 (프로젝트는 `NODE_VERSION=22` 설정)
7. 배포 후 Netlify HTTPS 주소가 열리는지 확인합니다.

## 3. OWNER 계정의 서버 권한 지정 — 반드시 필요

Netlify 프로젝트의 환경변수에 다음을 저장합니다 (**GitHub/코드 파일에 적지 말 것**):

```text
GARD_OWNER_EMAIL=오너가_실제_로그인할_이메일
```

- 설정 뒤 **Redeploy**합니다. 비어 있으면 서버는 모든 BOOK API를 503으로 차단합니다.
- 오너 여부는 클라이언트가 보내는 role이 아니라 **Netlify Identity 서버가 검증한 로그인 이메일**과 이 환경변수를 비교해 결정합니다.
- 프로젝트의 **Identity** 메뉴에서 **Enable Identity** 를 누릅니다.
- **Registration: Invite only**로 바꿉니다. 일반 방문자의 자유 가입은 사용하지 않습니다.
- Identity 화면에서 먼저 오너 주소를 **Invite user** 합니다. 이메일 초대장을 열고 비밀번호를 지정해 로그인합니다.

## 4. 33종 BOOK 로컬 원장 가져오기

1. 오너 이메일로 앱에 로그인합니다.
2. 첫 실행 시 **10자 이상 비공개 보관함 암호**를 생성합니다. 이 암호는 Netlify 로그인 암호와 다릅니다.
3. `JSON 가져오기` 버튼을 누릅니다.
4. 이전 대화에서 다운로드한 `GARD_BOOK_Discovery_Catalog_20261117.json`을 선택합니다.
5. '33종 가져오기'를 확인합니다.
6. 책별 `편집`에서 **공개용 요약**과 허용할 **구독자용 본문**을 입력합니다.
7. 최종 검토 후 해당 책만 **공개 승인**을 누릅니다. 공개 승인 전에는 서버에 해당 책의 정보가 없습니다.
8. 필요하면 게시된 책의 **PDF ↑**를 눌러 4MB 이하 PDF를 별도 승인 업로드합니다.
9. `암호화 백업`으로 보관함을 저장하고, 암호를 별도로 안전하게 보관합니다.

## 5. 구독자 초대와 BOOK 승인

1. Netlify 프로젝트 → **Identity → Invite users** 에서 구독자 이메일을 초대합니다.
2. 오너 앱의 `구독자 승인` 탭에서 **같은 이메일**을 입력합니다.
3. 해당 구독자에게 보여줄 BOOK의 체크박스만 선택합니다.
4. 필요하면 종료일을 지정합니다. `구독자 승인 저장` 클릭.
5. 구독자는 이메일 초대 수락 후 자기 계정으로 로그인합니다.
6. 오너가 허용한 BOOK만 자동으로 보입니다. 다른 BOOK ID를 추측해 API를 직접 호출해도 서버가 거부합니다.
7. 오너가 `철회`를 누르면 서버에서 새 데이터 조회 및 다운로드 요청을 거부합니다. **이미 다운로드한 PDF는 원격 회수할 수 없습니다.**

## 6. 로컬 백업과 복구

- 앱의 오너 원장은 `localStorage`에 **AES-256-GCM 암호문 형태**로 저장됩니다.
- `암호화 백업` 다운로드 → 별도 보관. **동일한 암호**로 복구합니다.
- 같은 컴퓨터에서도 브라우저/프로필이 바뀌면 로컬 원장은 자동 동기화되지 않습니다.
- 브라우저 데이터 삭제·기기 교체·암호 분실은 데이터 상실로 이어질 수 있습니다.
- 구독자에게 제공하는 목록과 PDF는 Netlify의 **서버 저장소**에 있고, 원본 로컬 보관함과 별도입니다.

## 7. 개발·검증

```bash
npm install
npm test
npm run build
```

- `npm test`: 데이터의 7분류/33종 가져오기, 허용필드, 승인·철회·만료, AES-GCM 암호화 등 단위시험.
- `npm run build`: 배포 빌드. Netlify 배포 시 CI에서 실행됩니다.
- Identity는 **로컬 `netlify dev`만으로 실제 인증 흐름을 완전히 검증할 수 없습니다.** 반드시 배포된 HTTPS 사이트에서 오너/구독자 **서로 다른 계정·브라우저**로 시험합니다.
- 실제 배포·구독자 초대·원고 PDF 다운로드·상용 거래는 이 패키지 생성 단계에서 수행하지 않았습니다.

## 8. 안전 설계의 경계

- 프런트엔드에 원본 33종 JSON, 사용자 이메일 목록, 인증 비밀값을 넣지 않았습니다.
- 서버는 `GARD_OWNER_EMAIL`이 설정되고 **생산(production)** 배포일 때만 데이터 API를 허용합니다. Deploy Preview에서 production Blobs가 수정되는 문제를 차단합니다.
- 공개 승인 기능은 **모든 시민에게 공개**한다는 뜻이 아닙니다. 실제로는 **서버에 게시 가능한 후보를 승인**하는 단계이며, 구독자 승인 없이는 누구도 볼 수 없습니다.
- 서버는 도메인 인증·메서드 검증·JSON 데이터 허용목록·PDF 헤더·크기 제한을 적용합니다.
- 서버측 검증 로직과 회원 데이터는 분리되어 있습니다.
- **다른 사람이 이미 받거나 복사한 파일을 원격 삭제할 수 없으며**, 출판권, 개인정보, 제3자 저작권 검토를 선행해야 합니다.
- Netlify Blobs는 소규모 선택 게시 자료 저장 용도입니다. 장기적으로 대규모 구독자/결제/감사 이력은 트랜잭션을 지원하는 DB와 결제 연계가 필요합니다.

더 자세한 출시 전 실사용 체크리스트는 `docs/QA_Release_Checklist.md`를 참고하세요.
